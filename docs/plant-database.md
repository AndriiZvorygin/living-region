# Plant database

`data/source/agroecosystem-plants.json` is the human-maintained catalogue.
`data/derived/plant-database.json` is generated by
`npm run build:agroecosystem-database` and is the normalized runtime contract.

Every record has a stable `id`, identity, architecture, establishment window,
site needs, harvestable `outputs`, ecological functions, management,
relationships and evidence. Each output has its own edible part,
`composition_id`, yield range, bearing curve, retention factor and possible
destinations. Output destinations are mutually accounted for by the annual
flow ledger: a harvested unit cannot be consumed, fed, exported and returned
to soil at the same time.

Evidence classes are explicit: `local_measurement`, `published_research`,
`government_extension`, `practitioner_observation`, `documented_synthesis`,
`explicit_proxy`, `scenario_assumption` and `reference_only`.

Yields and nutrient values use SI units: kg/ha/year, MJ/kg, kg/kg, g/kg or
the field-specific metric unit. Low/central/high values are ranges, not
confidence intervals unless the source says so. Unknown values are `null`.
The validator rejects duplicate IDs, invalid lifecycle/layer values, malformed
range ordering, negative quantities, duplicate output IDs, invalid bearing
factors and edible outputs without a composition link.

Cultivar-specific records should inherit from a species record only through a
generated, explicit override. They must retain their own evidence and cannot
silently replace a canonical cultivar with a proxy.
